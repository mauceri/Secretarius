Générez un exemple réaliste de message utilisateur adressé à Tiron, un assistant personnel,
ainsi que la commande et les arguments correspondants.

Tiron reconnaît les commandes suivantes :
- /c [#tags] [directives] <url|texte> — capturer une URL ou une note dans le wiki
- /ingest — lancer l'ingestion des captures en attente (sans argument)
- /wikistatus — afficher l'état du wiki (sans argument)
- /q <question> — interroger le wiki
- /source <url> [consigne] — lire une page externe maintenant (sans la sauvegarder)
- /chercher <critères> — rechercher des emails Gmail (mot-clé, expéditeur, période)
- /connecter — autoriser l'accès au compte Google (sans argument)
- /inbox [nombre] — lister les emails récents
- /repondre <contexte> — préparer une réponse à un email (brouillon, sans l'envoyer)
- /drive <critères> — rechercher des fichiers sur Google Drive
- /tags — lister les tags disponibles dans le wiki (sans argument)
- /kbupdate — mettre à jour la base de connaissances depuis le dernier clustering (sans argument)
- /lire <id> — lire le contenu d'un email par son identifiant (obtenu via /inbox ou /chercher, ex. 18ab3f2) ; uniquement un email, jamais une page wiki, une capture, un document Drive ou l'état du wiki
- /supprimer <slug> — supprimer une page du wiki (par son slug)
- /relire — obtenir la prochaine page du wiki à relire, la plus ancienne non vérifiée (sans argument)
- /verifie <slug> — marquer une page du wiki comme vérifiée (par son slug)
- /cron add <quand> [<canal>] <type> <contenu> — planifier un rappel, une commande ou une consigne (récurrent ou ponctuel), éventuellement sur un canal (sms, whatsapp, telegram, obsidian)
- null — demande hors périmètre de Tiron (rappel ou planification → /cron, jamais null ;
  composer un nouveau mail, consulter l'agenda,
  conversation informelle / humour ; toute question de connaissance → /q, jamais null /
  rédaction créative, ou toute autre action non couverte ci-dessus)

Directives pour /c : @simple (capture directe sans ingestion), file:<chemin> (inclure un fichier
local), ref:<slug> (wikilink vers un document existant).

Règles de génération :
- Le message doit être rédigé dans le registre indiqué (formel / familier / télégraphique / poli / abrégé).
- Le message doit illustrer le type de variante indiqué.
- Le message doit respecter les contraintes indiquées (moment, sujet, longueur, forme…).
- Le message doit être bref : une phrase, comme un vrai message tapé sur un téléphone (en général moins de 20 mots). Pas de formule de politesse développée, même en registre formel ou poli.
- Varier les tournures d'un exemple à l'autre : ne pas commencer systématiquement par « Bonjour » ni par le nom de l'assistant.
- Le champ args contient les arguments bruts passés après la commande (chaîne vide si la commande
  n'en prend pas).
- Langue : français uniquement.

=== CONTRAT IMMUTABLE — NE PAS MODIFIER ===
Entrées : intention, registre, variante, contraintes
Sorties : text (message utilisateur), command (commande Tiron ou null), args (arguments bruts ou "")
Les prompts intermédiaires doivent être rédigés en français.
=== FIN CONTRAT IMMUTABLE ===
